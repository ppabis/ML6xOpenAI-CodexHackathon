# AI-Native Workflow

## Full Lifecycle Flow

idea -> scope -> roles -> task breakdown -> architecture -> implementation plan -> build -> validate -> summarize -> demo

## Codex As A Partner At Every Step

- Thought partner: sharpen the idea and pressure-test feasibility
- Planning partner: break work into tasks, roles, and checkpoints
- Architecture partner: suggest a right-sized stack and shape tradeoffs
- Engineering partner: generate implementation work once the plan is clear
- Quality partner: define validation, tests, and review criteria
- Review partner: summarize changes, surface risks, and support handoff
- Demo partner: turn the build into a crisp story

## Why The Workflow Matters

Using Codex well is not only about generating code faster. In a one-day hackathon, the winning pattern is usually:

- clearer scoping
- faster decision-making
- better task parallelization
- fewer avoidable dead ends
- stronger demo readiness

## Mapping To The Hackathon Agenda

- Challenge selection and scoping:
  - define the problem
  - cut the idea down to one-day size
- Planning and architecture:
  - assign roles
  - choose the simplest stack that can prove the concept
- Implementation:
  - build a thin slice first
  - keep integration points small
- Quality and review:
  - validate the core path
  - capture evidence and limitations
- Demo preparation:
  - explain both the product and the AI-native way of working

## Practical Pattern

- Start with a demo outcome, not a feature wishlist.
- Keep one person owning scope sanity at all times.
- Ask Codex to present options and tradeoffs, not just answers.
- Revisit scope at midday.
- Log where Codex genuinely helped so the workflow itself is visible in the demo.
